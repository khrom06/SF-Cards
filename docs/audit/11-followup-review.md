# 11 — Follow-up: a second reviewer's five criticisms

After the audit, an independent reviewer raised five points. Each was checked against the code before acting. Result: **one was wrong, two were right and are fixed, one was partly right, one is a good suggestion that is now enforced.**

| # | Criticism | Verdict | What was done |
|---|---|---|---|
| 1 | `scripts/bench.mjs` ends with `process.exit(0)` after `finally`, so an error in the benchmark could be reported as success | **Wrong.** An exception thrown in the `try` block leaves the program after the `finally` block, with exit code 1; the `process.exit(0)` line is only reached on success. Reproduced: the same script with the measuring call replaced by one that throws exits with code 1. | Kept the behaviour, documented it in a comment, and added `test/tools.mjs` (run by `run.sh`): it makes the benchmark fail on purpose and requires a non-zero exit code. Mutation check: swallowing the error in `bench.mjs` makes the new test fail. |
| 2 | `scripts/taint.mjs` is not a blocking, exhaustive check: unreached interpolations only print, it is not in `run.sh` | **Right on the facts, and on one overstatement of mine.** In its first form the tool alone ran 1 339 of 2 020 interpolation sites with hostile data; my earlier sentence "all 2 047 interpolations checked by an instrumented run with hostile data" (report 10) mixed that run with the ordinary render suite and a hand review. The accurate figures: **1 345 sites reached by hostile data, 501 run only with benign data, 180 run by nothing**. All 681 were read by hand (the 180 one by one, the rest by definition / shape), none carries user text unescaped. | The tool now (a) runs inside `run.sh` and therefore in CI, (b) tries 8 shapes of hostile text (HTML and attribute break-outs, encoded entities, a literal unicode escape, `<style>` / `<script>` break-outs, expression syntax), (c) classifies each site (text, attribute, style attribute, `<style>` text, URL attribute, tag), (d) **fails** if an interpolation is not reached by a hostile scenario and is not on the reviewed list `test/taint-reviewed.json` (678 entries, each saying whether the benign suite runs it), (e) is stable: judged over up to 3 runs because a few branches depend on measured widths. Proof: it caught the two interpolations added later the same day (a constant, escaped tooltip text) and stayed green after they were read and recorded. Mutation check: `esc()` disabled ⇒ fails. Report 10 corrected. |
| 3 | The README "Requirements" still said "any recent version"; separate declared minimum, tested versions and unverified versions | **Right (documentation).** | Requirements now has three bullets: **Supported: 2024.11 and later** (oldest release the end-to-end test runs on), **Tested end to end:** 2024.11, 2025.6, 2026.1, 2026.10, 2026.11 (+ the CI matrix), **Not verified:** older than 2024.11 and the mobile apps beyond their web view. The Limitations section points to it. `hacs.json` still declares no minimum (it would block users whose older version may work). |
| 4 | 30 cards × 2 themes × 11 languages × states × sizes × versions: the set is getting hard to maintain; formalise a common contract, no more abstraction | **Good point, and cheap to enforce.** | A written **card contract** in `CONTRIBUTING.md` (what "finished" means) and **lint rule 9**: every card in the registry must have a full fixture (which puts it into every generic test automatically), an editor specification, a required-configuration rule (3 cards documented as needing none), and a place in the README and the demo. Mutation check: a missing fixture fails the lint. No new class or abstraction. |
| 5 | The battery card estimates the solar / grid split; make the difference between measured, calculated and estimated obvious | **Right.** The README said it, the card did not. | `sfBatSource` now returns whether the split is measured (a `from_grid` sensor) or estimated. When estimated, the battery card and the energy card show **≈** and a tooltip in the 11 languages; with a measured value the ≈ disappears. The README and the contract define the three categories (a sum or a share of two readings is "calculated" and shown as is). Tested for both cases and four languages; snapshots regenerated (22 battery renders, intended). Not done: the animated previews in `assets/anim/` still show the old text; they are regenerated at the next feature release. |
